# v0.29.1 release preflight

The [final unchanged benchmark gate](https://github.com/ZVN-DEV/powdb/actions/runs/41964111393)
passes on candidate `8508546560f7a280792d6ba37058f71f98e85e53`, compared
with fixed control `764ac1fbd26933b452d5f86f77fea4b9defe4138` on the same

`266feca22f791503df5d4b6a1c727b36e2bd0f21` has the identical source tree.

## Performance gates

- All 22 absolute workload checks pass.
- All 22 same-instance workload checks pass.
- All four unchanged ratio checks pass: point/B-tree 8.010x <= 9.5x;
  filtered count/B-tree 2624.040x <= 3500x; indexed update/point 1.452x <= 2x;

These are paired observations, not universal promises or competitor rankings.
Both slower write observations remain visible and are within the unchanged
gates. The legacy microbenchmarks use WAL Off and do not establish durable-write
throughput. Hardware variation affects absolute times; no cross-run/static-anchor
movement is credited as code-only improvement. The workflow retains raw control
and candidate Criterion estimates in its `criterion-estimates` artifact.

The separate [million-row read recovery](query-recovery.md) retains its original
released 0.29.0 control, exact answers, errors and restricted query-shape scope.
Passing these gates does not qualify an ORM, serverless service, mixed-write
concurrency profile, or every grouped/filtered aggregate.

## Correctness and packaging

- [Required full CI](https://github.com/ZVN-DEV/powdb/actions/runs/41964109098)
  passes, including Linux/macOS, release profiles, Miri, ASan, compatibility,
  deterministic fuzz replay, advisory checks and client/addon smokes.
- [Extended fuzz campaign](https://github.com/ZVN-DEV/powdb/actions/runs/41964114019)
  passes all eleven targets at 300 seconds per target.
- [Crate dry-run and patch API compatibility](https://github.com/ZVN-DEV/powdb/actions/runs/41964105471)
  pass for all eight published crates, including release-binary durability and
  package checks.
- [Addon dry-run](https://github.com/ZVN-DEV/powdb/actions/runs/41964108453)
  builds and tests macOS arm64, Linux x64 and Linux arm64, then validates the
  bundled package without publishing credentials.

Historical audit recovered two tiny valid-checksum index inputs that attempted
multi-gigabyte allocations. Serialized node/key/child counts now must fit the
remaining encoded bytes before reservation; variable lengths use overflow-safe
bounds checks. Both recovered inputs are permanent deterministic replay seeds.
Regression coverage includes twelve count cases, eighteen extreme variable
lengths, and six exact-minimum valid leaves across BIDX v1-v3. This is not a
whole-process RSS bound or general node-graph validation claim.

One October 24 historical B-tree fuzz failure has expired logs and no recoverable
input. Its exact cause cannot be declared fixed. This historical evidence gap is
retained alongside the current deterministic regressions and extended campaign;
no missing input is represented as a successful replay.

Publishing and live registry verification are separate from these preflight
results. See the versioned GitHub Release and publishing/smoke workflow runs for
channel availability.
