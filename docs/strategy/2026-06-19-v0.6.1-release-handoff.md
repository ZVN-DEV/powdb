## Release Intent

`v0.6.1` should be a narrow production-hardening patch release for the `v0.6.0`
metrics/SIGTERM release. It should not change the wire protocol, storage
format, or PowQL language surface.

Primary fixes:

- Enforce `POWDB_REQUIRE_TLS` for every credentialed auth path, including
  named-user auth and first-run admin bootstrap auth.
- Harden full and incremental backup restore manifests against path traversal,
  absolute paths, unexpected entries, and mismatched delta targets.
- Cap encoded row responses so one remote query cannot materialize an
  unbounded response body.
- Replace misleading query-timeout cancellation semantics with a safe threshold
  metric and non-detached completion behavior.
- Refresh active deployment examples away from stale release pins.

## Draft Release Notes

### Security

- `powdb-server`: `POWDB_REQUIRE_TLS=1` now covers shared passwords, named
  users, and bootstrap admin credentials. Plaintext credential auth now fails
  closed unless TLS is configured.
- `powdb-backup`: restore validates manifest file names before extraction and
  rejects traversal/absolute/separator/colon paths plus unexpected manifest
  entries. Incremental restore also verifies that each `.delta` belongs to the
  exact paged data file it updates.
- `powdb-server`: row responses larger than the configured hard cap are
  rejected before wire serialization with `result too large` guidance.

### Fixed

- Query timeout telemetry now reports threshold breaches instead of claiming
  cancellation of blocking executor work. The handler waits for the query to
  complete before replying, avoiding detached background writes after a timeout
  response.
- Active Docker/deploy docs no longer point users at stale `v0.4.8` images.

### Known Limitation

Full cooperative cancellation has not landed in this patch. The safe mitigation
is intentionally conservative for `v0.6.1`; the next implementation step is to
thread a cancellation token through long-running scan, sort, join, and mutation
loops as described in
`docs/strategy/2026-06-19-query-cancellation-hardening.md`.

- Get Kirby sign-off for release scope and public publication.
- Push `codex/hardening-0.6.1` and open a PR, or merge the hardening commit into
  the release branch through the normal repository flow.
- Create a dedicated version-bump commit:
  - root `Cargo.toml` workspace version to `0.6.1`

  - push the tag and verify GitHub release artifacts and container image

## Remaining Blockers

- No public release authority yet. Push, PR creation, tags, crates.io publish,
  npm publish, image publish, and public deploys all require Kirby sign-off.
- Version metadata still says `0.6.0` by design. A release commit must bump
  workspace, inter-crate, TypeScript, changelog, and release-index metadata.
- The current shell does not expose `npm`; the bundled runtime has `node` and
  `pnpm`, which was enough for the TypeScript suite and packed-client smoke,
  but the official `scripts/smoke-package.sh` should be rerun where `npm` is on
  `PATH`.
- Cooperative cancellation is not complete; `v0.6.1` contains the safe
  mitigation and a concrete follow-up plan.
- Benchmark/regression gates were not rerun during this handoff pass.
